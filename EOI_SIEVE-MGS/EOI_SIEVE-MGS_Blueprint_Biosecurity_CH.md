## 1. 问题陈述

一个实际运行的宏基因组监测项目每周产生约 10¹⁰ 条 reads。而最擅长识别"从没有人见过的病毒"的那类模型，根本跑不动它们。

这是结构性约束，不是资源抱怨。基因组基础模型确实实质性地提升了新颖病毒的识别能力——基于 DNABERT-2 构建的 ViraLM 是最清楚的例证 [1]——但它们对每条序列的推理开销在毫秒量级，比城市级汇水区的周度运行所能承受的速度慢四到五个数量级。领域内的标准应对是"先把问题变小"：先组装，然后对 contig 而不是对 read 打分。而这个应对恰恰在早期预警所在的区间失效：一个相对丰度 10⁻⁷ 的病原体在一份样本里只贡献个位数的 reads，永远拼不出 contig。**组装不是一个中性的提效步骤，它是一道灵敏度地板，而且正好铺在我们想要捕捉的信号底下。**

于是实际流程被迫在两个都会在关键情形上失效的选项之间二选一：一边是快速的、基于参考库的分类器——它在构造上就无法给库里没有的东西打分；另一边是准确的无参考模型——它在规模上负担不起，而且通常还被那道摧毁信号的组装步骤挡在前面。像 DeepVirFinder [2] 这样的深度 read 级分类器介于两极之间，但它诞生于基础模型时代之前，也没有针对"新颖性"（区别于"病毒性"）做过校准。

SIEVE-MGS 不是在这两难之间折衷，而是把它取消掉，依据的是一个观察：**如果把基础模型当作"教师"而不是"预测器"，它的代价就只在训练时付一次，而不在推理时付。** 我们把基础模型的表征蒸馏进一个紧凑的 read 级筛查器，使其在无需任何参考索引的前提下达到生产吞吐量；并且——因为一个要丢弃 99.99% 数据的滤网，只有在你能界定它丢掉了什么的时候才敢部署——我们为"被丢弃的真阳性 reads 所占比例"附上一个可证明的上界。

其成果不替代任何东西。它是一道前置滤网，任何现有项目都可以把它装在自己已经在跑的流程前面。

## 2. 技术路线

### 目标一 — 蒸馏出带召回保证的 read 级新颖性模型（第 1–7 月）

**为什么必须是蒸馏，而不是直接训一个小模型。** 这是本项目的科学内核，也是唯一一条可被证伪的主张。一个在留出分支（leave-one-clade-out）数据上从零训练的紧凑网络，学到的是"它见过的那些分支长什么样"，遇到真正超出这一经验的分支就会退化。强迫学生去匹配教师模型的**表征几何** [6,7]，迁移的是"病毒性"这一抽象结构，而不是对具体分支的记忆。因此训练目标包含两项：留出分支模拟数据上的监督损失，以及针对冻结的教师嵌入的表征匹配损失。**第 3 月的消融实验直接检验表征匹配项是否就是跨分支泛化的来源。** 如果不是，本项目的前提即为错误，而我们会早到还来得及调整的时候就知道。

**教师模型的选择是一项技术决策，而不是默认选项。** 最显而易见的候选恰恰是错的：Evo 2 出于生物安全考虑，刻意将感染真核宿主的病毒基因组序列排除在训练语料之外，其结果是它在真核病毒序列上表现出很高的困惑度 [3]——而那正是本项目关心的序列。因此我们把教师构建为一个组合：蛋白通道（对 reads 的六框翻译施加 ESM-2 [5]，在核酸层面同源性已被抹除处仍保留信号）与核酸通道（DNABERT-2/ViraLM 与 Nucleotide Transformer 家族 [1,4]）。教师仅在离线、仅在训练数据上使用，本身不属于交付物。

**标签来自构造，而不是来自教师。** 每一个被留出的分支会从所有参考库、训练集与教师拟合集中整体移除；随后在真实平台错误谱下从留出基因组模拟 75–300 bp 的 reads，并注入真实污水背景。真值因构造而精确。难度以"到最近保留邻居的 ANI"连续标定，而非二元的新颖/已知标签，并且所有结果按难度分层报告——因为汇总会掩盖 80% 以下同一性那个区间，而真正新颖的病原体恰恰落在那里。

**模型有两个输出头，因为污水里绝大多数"未知"根本不是病毒。** 我们分别估计 p(病毒源) 与 p(位于已知病毒空间之外)，只有两者同时高的 reads 才进入保留集。学生模型在结构上是一个反向互补等变的膨胀卷积网络 [8]，参数量 ≤5M，量化至 INT8，同时处理双链与 DNA/RNA 两类核酸，长读以重叠分块方式处理。

**保证才是它可部署的原因。** 借助 conformal risk control [9]，我们选取保留阈值 λ，使得真正新颖的 reads 落入**被丢弃集合**的期望比例不超过 ε，置信度为 1−δ。目标一的核心交付物不是某一个工作点，而是完整的 **(ε, 压缩比) 曲线**：你说出你能容忍多大的漏检率，我们说出数据能消失几个数量级。

我们同样会明确写出这个保证在哪里变弱。Conformal risk control 依赖可交换性，而不同汇水区、不同季节、不同文库化学之间并不可交换。因此我们按站点做滚动校准，并把"该界在跨站点、跨季节、跨测序平台的刻意分布漂移下退化多少"作为一项具名交付物报告，而不是塞进附录。

### 目标二 — 生产特性刻画与"即插即用"部署（第 4–12 月）

决定性的实验可以用一句话概括：**只喂给下游流程 0.01% 的 reads，它还能不能找到同样的东西？** 我们把 SIEVE-MGS 装在 nf-core/mag、mgs-workflow、Kraken2/Bracken 与 geNomad 前面，比较"全量输入"与"筛后输入"在回收类群、contig 与标记候选上的一致性，同时给出端到端的墙钟时间与美元成本。"**同样的答案，千分之一的算力**"这句话，决定了 CDC Biothreat Radar、NWSS 或 mSCAPE 这类项目是否真的装得上去——因此它是被测量出来的，不是被断言的。

另有三项刻画并行进行。

*吞吐与成本。* 每 GPU 与每 CPU 核的 reads/秒、商用云上每十亿 reads 的美元成本、常驻内存，以及一个边下机边打分、无需加载任何索引的流式模式。许多州公共卫生实验室根本没有 GPU，因此纯 CPU 路径是刚性需求而非附赠。我们的目标是在 A100 级 GPU 上达到 ≥5×10⁵ reads/s——即百亿 reads 的周度运行约需五个 GPU-小时——但**实测数字本身就是主要交付物**，无论结果如何我们都会公布。

*真实背景下的保留率。* 在模拟数据上压缩 10⁴× 什么也证明不了。我们在 CASPER（PRJNA1247874）、NWSS（PRJNA747181）、Tisza 等 2023（PRJNA966185）、Wolfe 等 2026（PRJNA1438722）以及 Zephyr/Broad 混合鼻拭子（PRJNA1052714）上实测保留率，后者同时检验筛查器能否迁移到复杂度与宿主占比不同的样本类型。如果真实污水只压得动 100×，我们就报 100×——因为 100× 在运营上依然是决定性的。

*历史突发事件上的召回。* 针对 2022 年 mpox 与 2024 年 H5N1 入污水，我们只问本项目该负责的那个窄问题：在存档数据中相关 reads 确实存在的最早时间点上，**筛查器把它们保留下来了吗？** 是否告警、何时告警是另一个问题，本提案不声称回答它。

## 3. 交付物与开放获取

`sieve` 将自第 3 月起以 MIT/Apache-2.0 许可在 GitHub 公开，全程开放开发而非在项目结束时一次性倾倒：PyTorch 训练代码、ONNX/TensorRT 部署路径、纯 CPU 回退实现，以及符合 nf-core 惯例的 Nextflow 模块——已经在跑 nf-core/mag 的项目只需增加一个步骤即可接入。预训练权重与逐站点校准工件发布至 Hugging Face 与 Zenodo（附持久 DOI），连同吞吐与保留率基准数据一并公开。预计产出两篇同行评审论文，均在投稿时同步预印。

我们**刻意不提议再建一个基准数据集**。凡是已有或将有的新颖病原体检测公开基准，我们都会在其上评测，并把我们的留一分支划分回馈给社区；本项目的贡献是模型、保证与实测运行成本。

## 4. 执行速度与风险姿态

本项目不需要任何湿实验、不需要新采样、不需要新硬件。所有主要数据集均为公开数据且已由本组下载完毕；GACRC 提供 GPU、CPU、存储与容器基础设施。分析在第一周即可开始。第 3 月的消融是一个带明确退路的真正 go/no-go，而不是一个不可能失败的形式检查点；真实数据上的保留率测量被刻意排在第 2 月，即在为一个真实背景可能根本不支持的压缩比投入大量精力之前。

## 5. 团队与能力

PI 拥有 40 余篇同行评审论文（h-index 24），横跨计算生物学与生物统计学，兼具统计方法学与实验设计的正规训练，以及当前在 Illumina、PacBio HiFi 与 Nanopore 三个平台上的生产级宏基因组工作经验。现有流程通过 Nextflow 与 Apptainer 在 GACRC 的 SLURM 集群上规模化运行，使用 sourmash、geNomad、VirSorter2、GOTTCHA2 与 Kraken2/Bracken。本项目所需的能力组合并不常见：一侧是深度学习工程，另一侧是无分布假设的不确定性量化，再叠加"一条宏基因组流程在规模上究竟要花多少钱"的一手经验。目标一里的那个保证不是装饰——它是一个公共卫生项目愿意丢掉 99.99% 数据的**唯一理由**，而把它陈述正确，首先是一个统计学问题，其次才是机器学习问题。

GACRC 提供全部计算、存储与容器基础设施；不申请任何新硬件。我们欢迎 Blueprint 引荐运营方伙伴（NWSS 参与水厂、佐治亚州公共卫生部、CASPER、Zephyr）以开展部署测试，也乐于与提交互补性 TA1 或 TA2 提案的团队组队——一个经过校准的前置滤网，对任何下游检测方法而言都是天然的集成点。

*同期提交声明：* 本组另行提交两份意向书——**NOVA-MGS**（TA1，在组装后 contig 上的无参考新颖性评分与证据核验）与 **DPD**（TA3，序贯检测统计学与"预算—预警时长"建模）。SIEVE-MGS 与二者在科学上相互独立，且在关键维度上不同：它作用于**未组装的 reads** 而非 contig，其目标是**召回保证下的吞吐量**而非校准后的排序，其交付物是一道位于任何检测栈**之前**的滤网而非一个检测器。三者各自完整自洽、独立立项、独立编列预算，任何一份都不以另一份获资助为前提。

## 7. 风险与应对

**表征蒸馏可能无法跨分支迁移。** 这是本项目的中心假设，也是最先被检验的一项。第 3 月的消融把蒸馏学生与"去掉表征匹配项、尺寸完全相同"的对照模型放在一起比较，并按"到最近保留邻居的 ANI"分层。如果该项毫无贡献，退路是放大学生模型——仍比教师快两个数量级——而这一发现本身也是可发表、对领域有用的结果。

**真实背景的压缩比可能远低于模拟数据。** 在第 2 月而非第 10 月于真实污水上测量。我们如实报告实际达到的压缩比；交付物是 (ε, 压缩比) 曲线，不是一个营销数字。

**可交换性失效会削弱 conformal 界。** 以逐站点滚动校准应对，并通过跨站点、跨季节、跨平台的刻意漂移压力测试加以量化。凡是该界不成立之处，我们照实写出并报告经验退化幅度。

**足够发散的病原体可能逃过任何学习到的表征。** 筛查器被刻意配置为高召回、低精度：我们界定的是**被丢弃的部分**，而不是被保留的部分。控制假阳性是下游流程的职责——这也正是本项目定位为前置滤网而非检测器的原因。

**单条 read 的分数本身很弱。** 单条 read 携带的信息有限，因此在产出任何候选之前，分数会先聚合到由 k-mer 或 minimiser 定义的 read 簇上；read 级与簇级的运行特性我们都会报告。
