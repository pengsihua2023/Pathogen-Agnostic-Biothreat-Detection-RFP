# SIEVE-MGS：蒸馏模型的流程与数据构成

写给项目内部理解与答辩准备用。对应 EOI 的 Aim 1。

---

## 0. 一句话和一个类比

**一句话**：请一位跑得很慢但很准的"专家模型"，离线把一批训练用的 reads 逐条看过；再训练一个极小的"学生模型"去模仿它，**不只模仿答案，还要模仿它的判断依据**；之后专家退场，学生以每秒五十万条的速度上线。

**类比**：

| 角色 | 对应 | 特点 |
|---|---|---|
| 世界级专家 | 教师模型（ESM-2） | 判断准，但看一条要几毫秒 → 每天百亿条根本看不完 |
| 实习生 | 学生模型（≤5M 参数 CNN） | 每条几微秒，但自己学容易死记硬背 |
| 培训方式 | **表征蒸馏** | 不只对答案，还要求"心里怎么想"和专家对齐 |

**为什么"模仿判断依据"是关键**：如果只让实习生背答案，他学到的是"我见过的这些病毒长什么样"；遇到从没见过的分支就废了。而让他对齐专家的**表征几何**，学到的是"病毒性"这个抽象结构——这正是新颖病原体检测需要的泛化能力。

> 这也是本项目**唯一可被证伪的核心主张**，第 3 个月的消融实验直接检验它（见第 6 节）。

## 2. 数据是怎么造出来的（本文重点）

### 2.1 先定义正类：viral 到底指什么（**待定的设计选择**）

这个定义决定整个训练集怎么造，必须先定下来。

| 定义 | 后果 |
|---|---|
| **任何病毒** | 污水病毒组里**噬菌体占绝对多数**。未知噬菌体会被全部保留 → **压缩比可能从 10⁴× 掉到 10²×**；而运维人员根本不关心噬菌体 |
| **感染脊椎动物的病毒**（推荐） | 与 RFP 聚焦 "human pathogens with pandemic potential" 一致；噬菌体明确归入背景；标签噪声大幅下降；与 ESM-2 教师也更配——真核病毒蛋白与噬菌体蛋白在表征空间里本来就分得开 |

> **建议采用后者**，并把 EOI 里的 `p(viral)` 改写为 `p(vertebrate-infecting)`。本文以下按后者叙述。

### 2.2 五类训练样本，以及它们**真实的**标签

⚠️ 这张表有两处最容易误读：

1. **模型的输入永远是一条 75–300 bp 的 read。** 基因组只是模拟的**原料**，模型从没见过整条基因组
2. **真实污水背景并不是干净的负样本**

| 训练样本（**全部是 75–300 bp 的 read**） | y_viral | y_novel | 说明 |
|---|:---:|:---:|---|
| **模拟 read** ← 留出分支基因组 | 1 | **1** | 我们要抓的目标，真值精确 |
| **模拟 read** ← 保留分支基因组 | 1 | 0 | 库里有的已知病毒 |
| **真实 read** ← 背景：细菌、人源核酸、食物、植物 | 0 | 0 | ✅ 干净负样本 |
| **真实 read** ← 背景：已知病毒（PMMoV、crAssphage…） | 1 | 0 | ⚠️ 比对参考库后**重新标注** |
| **真实 read** ← 背景：未知 / 未表征病毒 | 1 | 1 | ❌ **识别不出来，标签必然是错的**（见 2.7） |

上线时只保留**两个头都高**的 reads：既像病毒，又不像库里任何已知病毒。

> **注意上表的一个危险模式**：正样本几乎都是**模拟的**，负样本几乎都是**真实的**。这条相关性会被模型利用——见 2.6。

### 2.3 留出单元：clade 是什么、用什么聚、聚多少

留出法是"真值从构造中来"的核心，但"留出一个 clade"这句话里有三个未定项：**clade 指什么、用什么数据划、划成多少份**。

**（1）clade 不是分类阶元。**

| | 定义 |
|---|---|
| **clade（支系）** | 系统发育树上的**单系群**：一个共同祖先 + 全部后代。**不是层级** |
| species / genus / family | 林奈式**阶元**（ICTV 给病毒定了 15 级） |

被命名的分类单元理应是单系的，但**大量 clade 没有对应的名字**。病毒尤其麻烦：**ICTV 的种界定标准逐科各定各的，不存在跨科通用的相似度阈值**；各科规模极不均衡；而环境病毒中大量序列根本没有分类归属——偏偏新颖病原体最可能出现在那一片。

因此**不用阶元名定义留出单元**，改用序列相似度聚类：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 按 ICTV 阶元留出属/科 | 可解释 | 分类不均衡；未分类序列用不了 |
| **按序列相似度聚类**（采用） | 统一、可用于未分类序列、与难度轴一致 | 严格说不是系统发育意义的 clade |
| 按系统发育树切分 | 最有原则 | 跨科建树困难、需标记基因、成本高 |

**（2）用什么数据聚——以及一个必须绕开的坑。**

> ⚠️ **FastANI / skani 这类工具只在 ≥80% ANI 时可靠**：低于此值可比对片段占比塌陷，ANI 无定义。**而 80% 以下正是我们的目标区间。**

所以度量必须放到**蛋白层面**——AAI 在 30–40% 仍可用，覆盖整个目标区间。这也与 ESM-2 蛋白教师一致：**度量、聚类、教师三者同在蛋白层面，逻辑自洽**。

| 步骤 | 做法 |
|---|---|
| 1. 集合 | RefSeq Viral + GenBank 完整基因组，**按宿主过滤为感染脊椎动物者**（Virus-Host DB / NCBI host 注记），去冗余 |
| 2. 基因预测 | Prodigal（病毒模式）→ 每条基因组的蛋白集 |
| 3. 全对全比对 | DIAMOND / MMseqs2 |
| 4. 基因组间距离 | 互为最佳命中的 **AAI**，按共享基因比例加权（VIRIDIC / ViPTree 一类做法） |
| 5. 聚类 | 在 **~90% / ~70% / ~50% AAI** 三档做层次聚类或 MCL |
| 6. 对照 | 报告聚类与 ICTV 属/科的对应关系，给评审一个可解释的锚点 |

> **难度是基因组级属性。** 某条基因组到最近保留邻居的 AAI 算出后，**它模拟出的所有 read 继承该值**——不需要对 150 bp 的 read 去算 AAI，那没有意义。

**（3）聚多少份——折数不是直接定的，是阈值的产物。**

在阈值 T 处聚类，则整簇删除后，簇内任何一条到"最近保留邻居"的距离必然 < T（凡 ≥ T 者已在同一簇内一并删去）。

> **聚类阈值 T = 留出样本难度的上界。**

| 阈值 | 簇数 | 每折难度 | 对应场景 |
|---|---|---|---|
| ~90% AAI | 多而小 | 容易 | 已知病毒的新毒株 |
| ~70% AAI | 中等 | 中等 | 新的近缘病毒 |
| **~50% AAI** | 少而大 | **很难** | **真正的新颖病原体** |

**严格留一法不现实**：在 70% 处聚类仍有数千个簇，而每折都要重训一次。实际方案是**分组 K 折**：

| 项 | 设定 | 理由 |
|---|---|---|
| 难度层 | 3 层（90/70/50% AAI） | 够画出"性能 vs 发散度"曲线 |
| 每层折数 | **分组 10 折**，每折留出约 10% 的簇 | 依然无泄漏，成本降两个数量级 |
| **总训练次数** | **30 次**（3 × 10） | 约 600 GPU-小时，预算内 |
| 分层抽样 | 按 RNA/DNA、单/双链、宿主、簇大小分层 | 避免某一折全是同类病毒 |

**为什么是 10 折**：不同 clade 的难度差异极大，**折间方差才是不确定性的主要来源**；折数太少估不准。10 折是"可信区间"与"训练成本"之间的常规平衡点。

> 一次留出 10% 的簇比留出单个簇**更难**（保留下来的近亲更少），但因为报告的是**实测 AAI 分层**，这会自动体现在难度分布里，不造成偏差。

**（4）一个必须主动交代的泄漏：ESM-2 早就见过留出分支。**

我们把 clade 从学生训练集、参考库、教师参考集里都删了，**但删不掉它在 ESM-2 预训练时留下的痕迹**——UniRef 几乎包含所有已知病毒的蛋白。

要分清两种主张：

| 主张 | 留一法能否检验 |
|---|---|
| 学生能泛化到**自己监督数据**之外的分支 | ✅ 能 |
| 学生能泛化到**世界上从没见过**的病原体 | ⚠️ **不能**——ESM-2 见过 |

**但这不等于作弊**：部署时你本来也会用一个见过全部已知蛋白的 ESM-2，"教师知道所有已知蛋白"正是真实部署条件。

要检验更强的那个主张，**用时间切分**：只在 **ESM-2 训练截止（UniRef 快照约 2021–2022）之后才登录的病毒**上评测——这些序列 ESM-2 确实没见过，是干净的测试集。

> 这是评审能问出的最锋利的问题之一。**主动写出来是加分，被问出来是失分。**

### 2.4 难度用连续量标定，不用二元标签

每一条模拟 read 都继承其来源基因组的难度指标：**到最近保留邻居的 AAI**（平均氨基酸一致性；核酸 ANI 在 80% 以下不可测，见 2.3）。

- AAI 90% → 很像已知病毒，好抓
- AAI 50% → 高度发散，难抓
- **真正的新颖病原体通常落在 70% 以下**

所有结果**按难度分层报告**，不做汇总平均。因为汇总会被"简单样本"拉高，掩盖 80% 以下那个真正要命的区间。

### 2.5 模拟与混合的参数

| 项 | 取值 | 理由 |
|---|---|---|
| read 长度 | 75–300 bp | 覆盖主流 Illumina 配置 |
| 错误谱 | 平台真实错误模型 | 模拟得太干净，模型上线就崩 |
| 注入丰度 | 10⁻⁴ ~ 10⁻⁸ | 10⁻⁷ 是早期预警真正所在的区间 |
| 背景 | **真实污水 reads** | 真实噪声无法模拟：批次、降雨、稀释、宿主组成 |
| 双链 | 两条链都要 | 所以学生模型做成反向互补等变 |

**从基因组到 read。** 病毒基因组多数不到 1 Mb——RNA 病毒通常 10–30 kb，DNA 病毒 100–300 kb（几 Mb 是细菌与巨病毒的量级）。模拟时按随机起点、双链、目标覆盖度切成 reads：**一条 20 kb 的 RNA 病毒基因组在 30× 覆盖下产生约 4,000 条 150 bp 的 read**。跨 20–50 个留出分支折、每折数百个基因组，累计约 10⁷ 条模拟 read。


### 2.6 模拟 read 与真实 read 的域差：一条必须堵死的捷径

在 2.2 的构造里，**正样本几乎全是模拟的，负样本几乎全是真实的**。这留下一条完美的捷径：

> 模型只要学会区分"模拟痕迹 vs 真实测序痕迹"，就能在留出分支上拿到漂亮的分数——**而它完全没有学到任何生物学**。

上线立刻失效，因为上线时遇到的正样本也是真实 read。

**两者差在哪里：**

| 维度 | 模拟 read | 真实 read |
|---|---|---|
| 错误谱 | 按模型生成，规整 | 位置依赖、批次差异 |
| 质量值分布 | 平滑 | 有结构 |
| 接头 / 嵌合 / PCR 重复 | 一般没有 | 都有 |
| GC 偏倚 | 无 | 建库引入 |

**必须做的对照实验（排在第 3 月消融之前）**

从真实污水中挑出**能比对到某已知病毒的 read**，再从**同一株病毒的基因组**模拟出 read，两组一并送入模型：

| 结果 | 结论 |
|---|---|
| `p(viral)` 在两组间**无系统差异** | ✅ 模型学的是生物学 |
| **模拟组分数显著更高** | ❌ 模型在检测"模拟痕迹"，整套评测作废 |

> **这个对照必须先做。** 否则第 3 月的消融本身也不可信——你无法区分"表征匹配项带来了跨分支泛化"与"表征匹配项帮模型更好地识别了模拟痕迹"。

**缓解手段**

1. 用实测平台 profile（ART / InSilicoSeq），不用均匀错误率
2. **正负样本都各自包含模拟与真实两个来源**，破坏"模拟 = 正"这条相关性——这是最根本的一条
3. 注入背景时保留真实的质量值分布
4. 有条件时做 read 级域自适应

### 2.7 负样本不干净：这其实是 PU learning，不是二分类

**问题有多严重。** 2.2 表里的最后一类——背景中的未知病毒——**恰好就是我们要抓的那种东西**。把它们标成负样本，等于**在训练模型不要检出新颖病毒**。标签噪声正好落在正类上，是检测任务里最坏的一种情形。

**正确的统计框架。** 我们手上其实是：

- **可靠的正样本**：留出分支模拟出来的
- **未标注数据**：真实背景——是"未标注"，不是"已知为负"

这正是 **Positive-Unlabeled (PU) learning** 的标准设定，理论成熟。

**三步处理：**

| 步骤 | 做法 | 效果 |
|---|---|---|
| 1. 能识别的先清掉 | 背景 reads 比对 RefSeq viral / IMG/VR / 噬菌体库，命中的重标或移出背景 | 消除 2.2 表中第四类噪声 |
| 2. 剩下的按未标注处理 | nnPU（非负风险估计）或 Elkan–Noto 重加权，而非普通 BCE | 不再把未知病毒当负样本惩罚 |
| 3. 估计并修正 | 估出背景中正类比例 π，据此修正报告的假阳性率 | 报出的 FP 不再把真阳性算进去 |

**它还直接冲击压缩比这个卖点。** 若污水里未知病毒暗物质占比不低，筛查器会把它们**全部保留**——而且模型判断并没有错。后果是压缩比从 10⁴× 下滑。提案里"第 2 月就在真实数据上测保留率"和"若只压得动 100× 我们就报 100×"，防的正是这个。

> 评审看到"我们知道负样本不干净，并且用 PU learning 正面处理"，远比看到一张干净的 (0,0) 表要信服。这是把弱点变成加分项的地方。

## 3. 教师模型：只用 ESM-2，为什么

### 3.1 核酸语言模型在这里不可用（两条独立的理由）

**理由一：语料里没有病毒。**

| 模型 | 训练语料 | 问题 |
|---|---|---|
| Evo 2 | 出于生物安全**刻意剔除**了感染真核宿主的病毒 | 在正是我们要找的序列上困惑度很高 |
| Nucleotide Transformer | 3,202 个人类基因组 + 850 个物种基因组 | 宿主基因组，几乎没有病毒 |
| DNABERT-2 | 多物种基因组 | 同上 |
| ViraLM | DNABERT-2 上做病毒微调 ✅ | 但它作用于**组装后的 contig**，不是 read |

**理由二：我们的 read 太短，而且核酸信号本来就已经没了。**

- 一条 150 bp 的 read 在这些模型的分词下只有 **30–40 个 token**，而它们按**千碱基级上下文**训练——等于在分布外使用
- 更根本的：**低于 80% ANI，信号大体已经离开了核酸字母表**。而 80% 以下正是真正的新颖病原体所在的区间

> 所以单通道不是"我们简化了"，而是**核酸通道在目标发散区间本来就没有信号可提**。

### 3.2 蛋白层面还在

核酸一致性衰减得比蛋白快得多。核酸 70% 一致时，蛋白往往仍有 80–90% 一致——衣壳、聚合酶、糖蛋白的折叠特征还在。

**ESM-2 的 UniRef 训练语料确实包含病毒蛋白**，这一点和 Evo 2 正好相反。

### 3.3 教师怎么用

```
read（150 bp）
   │
   ├─ 6 框翻译 → 6 条 ~50 aa 的肽段
   │
   └─ 每条肽段 → ESM-2 → 嵌入向量
                    │
                    └─ 跨 6 框汇合（pooling）→ z_teacher（存盘）
```

**存下来就完事了。** 之后训练学生反复读这些向量，不再跑 ESM-2；上线更是完全不涉及教师。

### 3.4 不含编码内容的 read 怎么办

这是单通道设计必须回答的问题。三点：

1. **不是盲区**：这类 read 的六个框翻译出来都是"不像蛋白的东西"，会被嵌到远离蛋白空间的位置——**这本身就是信息**
2. **占比不高**：病毒基因组基因密度很高，RNA 病毒通常超过 90% 为编码区
3. **先验证再投入**：约 50 aa 短片段上的嵌入质量，作为**第 1 月的检查项**先做掉

## 4. 学生模型：结构与为什么

### 4.1 结构

```
输入：一条 read，one-hot 编码  4 × L   (L = 75–300)
   │
   ├─ Stem：conv1d(4→64, k=9)
   │
   ├─ Stage 1：3 × [conv1d(64→64, k=5, dilation=1,2,4) + Norm + GELU + 残差]      L=300
   │      ↓ stride-2 下采样
   ├─ Stage 2：3 × [conv1d(96→96, k=5, dilation=1,2,4) + Norm + GELU + 残差]      L=150
   │      ↓ stride-2 下采样
   ├─ Stage 3：4 × [conv1d(128→128, k=5, dilation=1,2,4,8) + Norm + GELU + 残差]  L=75
   │
   ├─ 全局池化（mean ‖ max 拼接）→ 定长向量     ← 让 75–300 bp 共用一个模型
   │
   ├─► 头1：p(viral)                     1 个 logit
   ├─► 头2：p(outside known viral space)  1 个 logit
   └─► 投影头 → z_student (256-d)         ← 只在训练时用，上线时整个丢掉
```

### 4.2 每个选择的理由

**为什么是 CNN 而不是 Transformer。** 吞吐量。注意力在 L=300 上是 O(L²) 且算术强度低；CNN 是固定成本的卷积栈，GPU 上批处理效率高、CPU 上能向量化，而且 **INT8 量化比注意力干净得多**——注意力的 softmax 与长尾激活对量化很敏感。

**为什么是空洞卷积（dilated）。** "蛋白编码特征"不是局部信号：密码子周期性、ORF 结构要看到 50–100 bp 的跨度。空洞率按 1,2,4,8 翻倍，几层就能把感受野铺满整条 read，不必堆很深。

**为什么必须反向互补等变。** 一条 read 来自哪条链是随机的，模型必须对 `x` 和 `revcomp(x)` 给出**同一个分数**。两种做法：

| 做法 | 代价 |
|---|---|
| 跑两遍再池化 | 简单，但**推理成本翻倍** |
| **卷积核参数绑定**（Shrikumar et al.） | 等变性由构造保证，**零额外成本** ✅ |

这不是锦上添花：不做的话，同一 DNA 片段测到正链和负链会得到两个不同分数，**conformal 的保证直接失效**。

**为什么要全局池化。** read 长度不固定（75–300 bp，加上长读分块）。池化把任意长度压成定长向量，**一个模型通吃所有平台**，不必为每种读长各训一个。

**投影头为什么上线时丢掉。** 它只服务于表征匹配损失（对齐教师嵌入）。训练一结束使命即完成——**上线只保留两个分类头**，推理成本再降一点。

### 4.3 算力预算对得上

| | 值 |
|---|---|
| 参数量 | **约 1M**（提案写 ≤5M，留了扩展余量） |
| 每条 read 计算量 | **约 1.3×10⁸ FLOPs** |
| A100 实际可用算力（INT8，保守） | ~10¹⁴ OPS |
| 反推吞吐 | 10¹⁴ ÷ 1.3×10⁸ ≈ **7.7×10⁵ reads/s** |

提案里的目标是 ≥5×10⁵ reads/s——**这套配置算出来 7.7×10⁵，留了约 1.5 倍余量**。那个目标不是拍脑袋的，是从架构反推的。

> **早期下采样是关键。** 若全程保持 L=300、128 通道，计算量约 1 GFLOP/read，**超预算 5 倍**。分三段逐步下采样（300→150→75）同时加宽通道，是感受野与算力之间的平衡点。

### 4.4 一个必须如实记下的弱点：CPU 路径

按 1.3×10⁸ FLOPs/read 与单核 ~10¹¹ OPS（AVX-512 VNNI 理想值）估算：

- **约 770 reads/s/核**
- 每天十亿条 → 约 **360 核心小时/天**，即十来个节点常开

这比乐观估计高一个数量级。现实应对是**给 CPU 单独出一个更窄的模型档位**（通道减半、层数减少，以精度换吞吐），并把它作为交付物的一部分。

> 提案正文只承诺"实测 reads/s per GPU 与 per CPU core，数字本身即交付物"，**没有写死 CPU 的核心小时数**——这一点是安全的。但内部预期应当按上面这个量级来放。

## 5. 损失函数：两项，这是蒸馏的全部

```
总损失  =  监督项  +  λ × 表征匹配项
```

**监督项**：两个头对 (y_viral, y_novel) 的交叉熵。因为新颖样本极少，要做类别加权。
→ 教学生"答案是什么"

**表征匹配项**：学生投影头输出的 z_student 与教师存下的 z_teacher 之间的余弦距离。
→ 教学生"专家是怎么想的"

**λ 就是这个项目的赌注。** λ=0 就退化成普通的小模型训练；λ>0 才叫蒸馏。

> 表征蒸馏的完整说明——为什么这里只能用它、为什么它能跨分支泛化、以及为什么不先把 ESM-2 微调成分类器——见 [`SIEVE_表征蒸馏详解.md`](SIEVE_表征蒸馏详解.md)。

## 6. 第 3 个月的消融：整个项目押在这一步

训练两个**结构完全相同、参数量完全相同**的学生：

| | A 组 | B 组 |
|---|---|---|
| 监督项 | ✅ | ✅ |
| 表征匹配项 | ❌（λ=0） | ✅（λ>0） |

在**留出分支**上按 AAI 分层比较 AUPRC。

- **B 组在低 AAI（<70%）区间明显好于 A 组** → 主张成立，项目继续
- **两组没差别** → **本项目的前提是错的**，第 3 个月就知道，退路是放大学生模型（仍比教师快两个数量级），而这个否定结果本身也值得发表

> EOI 里那句 "If it is not, the premise of this project is wrong and we will know early enough to act" 指的就是这个。

## 7. 上线：打分之后怎么定阈值

学生模型给每条 read 两个分数，但**分数本身不能直接用**——你得知道"卡在哪里"会漏掉多少真货。

**conformal risk control** 解决这个问题：

1. 留一份校准集（与部署数据可交换，**按站点分别校准**）
2. 对一系列候选阈值 λ，算出"真正的新颖 read 被丢掉的比例"
3. 选出**在置信度 1−δ 下，漏检率仍 ≤ ε** 的最激进阈值

最终交付的不是某一个工作点，而是一条 **(ε, 压缩比) 曲线**：

> 你告诉我能容忍多少漏检，我告诉你数据能压掉几个数量级。

**这个保证会在什么时候失效**，我们也照实报告：conformal 依赖可交换性，而不同集水区、季节、文库化学之间并不可交换。所以做逐站点滚动校准，并专门测跨站点/季节/平台漂移下这个界退化多少。

## 8. 算力与数据量（具体数字）

| 环节 | 量级 | 成本 |
|---|---|---|
| 参考病毒基因组 | 10⁴–10⁵ | — |
| 留出实验 | 3 难度层 × 分组 10 折 = **30 次训练** | — |
| 模拟新颖 reads | ~10⁷ 条 | CPU，小时级 |
| 真实背景 reads | 10⁷–10⁸ 条 | 已下载 |
| **教师嵌入（一次性）** | 10⁷ 条 × 6 框 = 6×10⁷ 条序列 | **约 5–20 GPU-小时**（ESM-2 650M；用 3B 模型则 ×10） |
| 学生训练 | 30 次 × 约 20 GPU-小时 | **约 600 GPU-小时** |

> 预算里那条 **$30,000 GPU** 主要就是给"教师嵌入 + 学生训练 + 跨硬件吞吐基准"三项的。上线本身很便宜——**这正是整个项目的卖点**。

## 9. 最容易被误解的几点

| 误解 | 实情 |
|---|---|
| "上线时要跑大模型，太慢" | ❌ 教师只在训练前跑一次，上线只有 5M 参数的学生 |
| "蒸馏就是把大模型压小" | ❌ 常规蒸馏是对齐**输出**；这里对齐的是**表征**，目的是跨分支泛化而不只是压缩 |
| "学生模型要先翻译成蛋白" | ❌ **学生从不翻译，也从不看见蛋白**。它学的是直接在原始核酸里识别 ESM-2 翻译后才能看到的特征 |
| "整条病毒基因组进模型？" | ❌ 模型输入**永远是一条 75–300 bp 的 read**。基因组只是模拟的原料，模型从没见过它 |
| "模拟 read 和真实 read 差不多吧" | ❌ 差别足以让模型走捷径去认"模拟痕迹"。必须先做对照实验，见 2.6 |
| "真实污水背景就是负样本" | ❌ 背景里含**已知病毒**（可重标）与**未知病毒**（识别不出）。正确框架是 PU learning，见 2.7 |
| "标签从哪来？靠教师打标？" | ❌ 标签来自**构造**（留出分支 + 模拟），是精确真值。教师只提供表征，不提供标签 |
| "SIEVE 是个检测器" | ❌ 它是**前置滤网**。它界定的是**被丢掉的部分**，不承诺低假阳性——控假阳性是下游的事 |
| "组装一下再判断不是更准？" | ❌ 组装在 10⁻⁷ 丰度直接失效（几条 reads 拼不出 contig），而那正是早期预警所在的区间 |
